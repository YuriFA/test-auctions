# SDD-023 Bets ViewModel And UI

## Статус

Не начато.

## Цель

Отрендерить историю ставок аукциона удобным для просмотра образом.

## Охват

- Загрузить данные bets.
- Построить производные значения представления (view-model).
- Показать количество участников, ранжирование, ценовые поля и empty-состояния.
- TDD: тесты на view-model мапперы пишутся ПЕРВЫМИ, до UI.

## Зависимости

- `SDD-013`
- `SDD-022`
- vitest-раннер из `SDD-015`

## TDD-порядок

1. Написать красные тесты на чистый view-model mapper (например `buildBetsViewModel(betsResponse, options)`):
   - количество участников выводится из уникальных `organization_id` активных ставок (D-010), а не из отсутствующего поля API;
   - ранжирование ставок отражает `place` и `is_rejected` корректно: отменённые ставки попадают в отдельную группу/секцию;
   - empty-состояние: пустой массив ставок → явный флаг `isEmpty`, не `null`/`undefined`;
   - null-ценовые поля (`price_with_vat`/`price_no_vat`) не падают; mapper использует safe-accesсы;
   - скрытая история (`hide_bets_history` restriction) → mapper возвращает явный `isHidden`-флаг, UI решает показывать ли placeholder.
2. Запустить тесты, убедиться, что они красные по правильной причине.
3. Реализовать минимальный mapper, чтобы тесты позеленели.
4. Построить UI поверх готового view-model.

## Критерии приёмки

- Список ставок рендерится с обязательными полями.
- Количество участников последовательно выводится из доступных данных.
- Empty-состояния и информация об отменённых ставках видимы.
- View-model mapper покрыт тестами в `pnpm test`; UI потребляет только типизированный view-model, не сырой DTO.

## Заметки и риски

- Производные значения должны быть задокументированы, когда API не экспонирует их напрямую.
- Тесты на mapper не требуют рендеринга React: чистая функция → `describe`/`it` с DTO-фикстурами.
- UI-тесты (Rendering, accessibility) вне scope logic-минимума; при желании их можно добавить позже, не смешивая с TDD-тестами mapper'а.
