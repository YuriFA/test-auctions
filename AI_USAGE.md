## Замечания о текущем покрытии

- Все запланированные SDD-задачи завершены: `SDD-001..028` + `SDD-030` (active filter chips) + `SDD-031` (эта финальная документация). `SDD-029` пропущен при нумерации (gap).
- UI полностью реализован end-to-end: список с фильтрами и карточками, detail-страница с restriction-флагами, bets-history (nested route), форма ставки с stepper и валидацией, chip-блок активных фильтров.
- Логические тесты (314 в 17 файлах) покрывают чистую логику (URL-контракт, request builder, VM-мапперы, restriction derivation, primary-action priority, formatters, badge variants, bet-form schema, filter-chips) + MSW-handler integration (cross-endpoint консистентность после `writeBet`).
- Browser smokes (21 в 6 spec'ах) покрывают routing, list-page behavior, filters UI, bet-form stepper, MSW browser integration, mutation-flow между экранами.
- Не автоматизировано: визуальные регрессии, mobile-specific rendering (только один 375px smoke в `filters-ui.spec.ts`), реальный backend (только MSW).
- `SDD-005`: TanStack Router в code-based режиме (`RouterProvider` + `QueryClientProvider` в `app.component.tsx`); QueryClient-синглтон в `app/lib/`; маршруты в `app/routes/`, страницы в `pages/<slice>/ui/`.
- `SDD-007`: адаптер превращает `RequestResult` Hey API в `ApiError`/`ApiValidationError`; граница `generated` держится на структуре папок и Public API.
- `SDD-008`: иерархические ключи делают bets потомком detail — план инвалидации читается как документация. steiger-правило `fsd/insignificant-slice` остаётся отключенным: `entities/auction` и `features/auction-filters` имеют по одному потребителю (`pages/auctions-list`) до SDD-018/20.
- `SDD-010`: один module-level `state.auctions` для всех handler'ов; мутация `writeBet` отвергает предыдущую активную ставку, пересчитывает места, обновляет trading-блок в list+detail DTO согласованно. 404 на неизвестном UUID, 422 на `price <= 0`.
- `SDD-011..014`: каждый handler — тонкая HTTP-обёртка над store, владеет только HTTP-конвертом; path-паттерн `*/api/v1/auctions/...` с leading-wildcard работает и в browser-worker, и в Node `setupServer`. Односегментный placeholder `:auctionUuid` + метод-диспатч MSW держат handlers без конфликтов.
- `SDD-014`: спецификация помечает 200-ответ set-bet как `unknown`; адаптер `placeBet` возвращает `void`, mock тем не менее отдаёт `BetItem` — forward-compatible.
- `SDD-015`: контракт в `features/auction-filters` (новый feature-слайс). Реализация без runtime-Zod — это прямая JSON-подобная трансформация; Zod пригодится в SDD-025. URL не содержит admin-only полей (`customer`, `per_page`).
- `SDD-016`: builder `buildAuctionListRequest` — чистая функция `AuctionsListFilters → AuctionListRequest`. Default-значения не отправляются (пустой фильтр → `{}`), `auc_type: 'Unknown'` отсекается (UI-only), `weight_*`/`volume_*` намеренно не маппятся (D-014). Canonical-имя `AuctionListRequest` добавлено в Public API `shared/api` (ранее был только alias `AuctionListFilters`).
- Тесты: MSW-handler integration (`src/shared/api/mocks/handlers/*.test.ts`, ~31 assertion в составе `pnpm test:run`) покрывают list/detail/bets/set-bet через `msw/node` `setupServer`; browser-smokes (`e2e/*.spec.ts`, 21 тест в составе `pnpm test:e2e`) — Playwright-runner, сам поднимает vite через `playwright.config.ts` `webServer`.

## Какие решения принял кандидат

- **Стек**: Hey API codegen (только SDK+типы), рукописный TanStack Query, code-based TanStack Router, Zustand для точечного UI-state, URL search params как источник истины для фильтров, Tailwind + shadcn/ui, история ставок как вложенный маршрут.
- **Именование**: `*.component.tsx` для всех React-компонентов, `.route.tsx` для маршрутов, `*.test.ts` для тестов (co-locate рядом с тестируемым модулем).
- **Границы**: сгенерированный OpenAPI-слой read-only и изолирован за `shared/api`; query-ключи в одной иерархической фабрике; mock-датасет не реэкспортируется из `shared/api/index.ts`; `msw/browser` изолирован в `mocks/browser.ts` и не реэкспортируется из `mocks/index.ts`.
- **`writeBet` возвращает discriminated union** `PlaceBetResult` вместо бросания — хранилище отвечает за данные, HTTP-семантика за handler'ом (SDD-014).
- **Направление аукциона** (`Down` — младшая выигрывает, `Up` — старшая) — единственный сигнал для ранжирования и перевычисления `available`.
- **Автоматическое отвержение предыдущей активной ставки** пользователя при новой (как в сиде `stoppedRejected`).
- **Path-паттерн `*/api/v1/auctions/...`** с leading-wildcard для browser+Node; односегментный `:auctionUuid` placeholder + MSW-диспатч по методу держат 4 handler'а без конфликтов.
- **MSW worker стартует с `await` перед `createRoot`**, поэтому ни один fetch не уходит до готовности воркера; dynamic import в `import.meta.env.DEV` вырезается Vite в production.
- **`tsx`** (не `--experimental-strip-types`) для smoke-скриптов — extensionless-импорты в generated не требуют renaming.
- **TDD per-task**: тесты пишутся вперёд в задаче, создающей тестируемый код (SDD-015/16/24/25); выделенная задача «Logic Tests» не заводится, TDD встроен в задачи-источники (см. `docs/sdd/decisions.md` D-008).
- **Двусторонний URL-контракт в SDD-015** (D-012): parse + serialize + defaults в одном модуле; default-значения не сериализуются.
- **Display-лейблы для enum'ов** (D-013) в `entities/auction/lib` как `Record<Enum, string>`; первый потребитель — SDD-018.
- **Resolver `auctionRef -> auctionUuid`** (D-011 updated) закрывает контрактный разрыв: внешний route param строится от `main.order_uid`, а adapter-layer резолвит его в настоящий `auctionUuid`, нужный OpenAPI path-эндпоинтам.
- **Page structure: shell + content.** `AuctionsPage` (frame + header, ноль пропсов, ноль hooks) оборачивает `AuctionsList` (все hooks, ранние return'ы для skeleton/error/empty, success-рендер). Public API слайса экспортирует только shell, content — внутренний.
- **Export-naming без `Component`-суффикса.** Файлы остаются `*.component.tsx` (требование AGENTS.md), но идентификаторы экспорта короткие: `AuctionsList`, `RootLayout`, `Button`. Раньше был mix `AuctionsListComponent`/`Button` — привёл к единому стилю.
- **VM-mapping через `select` в query-hook'е**, не в рендере. `useAuctionsList` имеет `select: toAuctionsListViewData`, который мапит `AuctionListResponse` → `{ items: AuctionListItemVM[], currentPage, lastPage, total }`. Маппинг бегает один раз на новый snapshot, не на каждый render.
- **Типизированный URL search через `validateSearch`.** На route: `validateSearch: parseAuctionsListSearch` (возвращает `Partial<AuctionsListFilters>` — только non-default поля). На router: кастомные `parseSearch`/`stringifySearch` через `URLSearchParams` (повторяющиеся ключи для массивов, undefined/empty пропуски). `useSearch({ from: '/' })` типизирован без `as`-cast'а. Page merge'ит partial с `DEFAULT_AUCTIONS_LIST_FILTERS` для downstream-потребителей.
- **Presentational-компоненты получают generic intent-callback'и.** Карточка принимает `onIntent?: (auctionUuid) => void` (hover/focus-триггер), не `onPrefetch`. Карточка не знает, что page делает с этим сигналом; page решает (prefetch query).
- **SDD-020: VM-mapper централизует nullable-обработку и enum→label.** `toAuctionListItemVM` построен так, чтобы карточка оставалась чистым рендером: каждое nullable-поле DTO схлопывается в `string | null` с явным fallback `''`/`null`, а enum'ы превращаются в русские лейблы через `describe*`. Карточка не импорит `AuctionStatus`/`describeAuctionStatus` и не знает о структуре DTO. 8 TDD-тестов покрывают happy-path, missing-uuid, missing-direction с fallback на города, null-price и missing-trading.
- **SDD-020: логика primary action живёт в чистой функции.** `deriveAuctionCardPrimaryAction` возвращает discriminated union одного из 4 состояний (`place-bet`/`change-bet`/`view-bets`/`disabled`). Терминальные статусы (`Finished`/`Stopped`/`Canceled`) форсят disabled с status-specific лейблом, перебивая `can_set_bet`. 8 TDD-тестов покрывают приоритет и все ветки. Карточка только рендерит результат; SDD-022/23/26 потребляют route без правок логики.
- **SDD-020: stretched-link вместо вложенных `<a>`.** Карточка — это `<article>` с одной stretched `<Link>` поверх всего контента (кликабельно всё) и второй `<Link>` для CTA с `z-10`, чтобы он перебивал stretched-overlay. HTML остаётся валидным (нет вложенных `<a>`), а CTA ведёт на корректный подсегмент (`/bet` или `/bets`) — два разных Link-рендера держат `to` строковым литералом для типизированного `params` TanStack Router.
- **SDD-020: `step` не попал в карточку.** List-DTO `trading.price` содержит только `{start, current, current_no_vat}`; `step` есть только в detail. Карточка не делает вид, что знает шаг, и не дёргает detail-эндпоинт — поле опущено и задокументировано здесь. Если будущая ревизия API добавит `step` в list-DTO, VM-маппер расширяется одним полем без правок UI.
- **SDD-021: VM-mapper `toAuctionDetailVM` повторяет паттерн list'а.** Один `select` в `useAuctionDetail` мапбит `AuctionShowResponse` → `AuctionDetailVM`. Все nullable-поля DTO схлопываются в `string`/`null`/`undefined` с явным fallback; enum'ы (`AuctionType`/`AuctionStatus`/`TradingStatus`/`OperationType`/`PaymentDelayType`/`BidMeasurementType`) → русские лейблы через `describe*`. Страница не импортит типы DTO и не вызывает `describe*` в рендере — только читает VM. 11 TDD-тестов покрывают happy-path, empty-DTO, nullable-цены, restriction-флаги, fallback-лейблы и contact/route-mapping.
- **SDD-021: restriction-флаги изначально читались прямо из VM, без central-handler'а.** SDD-022 тогда ещё не начался — detail тянул `hidePointsAddressAndContacts`/`noViewCargoPrice`/`hideBetsHistory`/`canSetBet` как 4 boolean'а из VM. Замена оказалась ровно такой, как планировалось: одна точка в `AuctionDetailContent` (заменить прямые чтения на `deriveAuctionRestrictions(vm)`), UI-дети не трогаются за исключением сигнатуры. Floating-point epsilon `1e-6` защищает от `0.01 / 0.03`-дрейфа; `step <= 0` отключает проверку (контракт может дать `null`).
- **SDD-025: `available` — UI-подсказка, не part of schema.** Поле `trading.price.available` из detail DTO подсказывает «следующая разумная цена», но контракт не энфорсит его как жёсткое ограничение — поэтому `available` вообще не входит в `BetPriceConstraints`. Этого достаточно для контракта, но не покрывает реальный user-flow — что видит пользователь после сабмита формы. Поэтому добавлен `mutation-flow-smoke.mjs`: реальная мутация через UI `/bet` → навигация на `/bets` → SPA-переход на detail → SPA-переход на list, с assertion'ом обновлённой цены на каждом экране. Это закрывает SDD-028 acceptance criteria "текущая цена / торговый статус / история / своя ставка обновляются там, где ожидаются".
- **SDD-028: MSW 2.x исполняет handlers в контексте страницы, не SW.** Service Worker только перехватывает запросы и передаёт их в client via `postMessage` — handlers бегают в JS-контексте активной вкладки. Therefore module-level state в `runtime/store.ts` переинициализируется при каждом полном `page.goto`. Чтобы сохранить state между шагами smoke (ставка → bets → detail → list), навигация делается через SPA click по `<a>`, не через Playwright `goto`. Побочный эффект: end-to-end smoke реально проверяет invalidate-флоу TanStack Query — после `usePlaceBet.onSuccess` list/detail/bets query'и помечаются stale и ре-фетчатся при следующем mount'е соответствующего hook'а.
- **SDD-028: форматтер `formatPrice` использует NBSP.** Playwright `textContent` возвращает "44 000 ₽" с NBSP (` `) между цифрами, не обычным пробелом. Regex-assertion построен как `digits.split('').join('[\\s\\u00A0]?')` — толерантно к любому whitespace-разделителю, иначе точное сравнение `=== '44 000'` падало бы на невидимом символе.
- **SDD-027: stepper +/- вокруг поля цены.** Когда `step > 0`, поле цены рендерится не как голый `Input`, а как `InputGroup` с двумя `InputGroupButton` (lucide `Minus`/`Plus` иконки) в `inline-start`/`inline-end` addon'ах. Клик `+` вызывает `nextStepPrice(current, constraints)`, `−` — `prevStepPrice`; обе функции чистые и живут в `bet-form-schema.ts` (15 TDD-тестов покрывают missing-step, alignment от base 0 и ненулевого base, clamp к min/max, boundary-кейсы). Snapping — не literal `current ± step`: `Math.floor((current - base) / step)` + 1 (для `+`) или `Math.ceil(...) - 1` (для `−`) гарантирует, что результат всегда step-aligned от `base`, даже если пользователь ввёл misaligned значение руками. Клик `+` из пустого input'а сеет от `available ?? min ?? base ?? 0` и сразу делает шаг вверх — для downLeading seed это даёт `available(44500) → 45000` (ближайшее выравненное от `start`).
- **SDD-027: stepper disable'ится на границах и во время мутации.** `+` disable'ится, когда `nextStepPrice(current) === current` (текущее уже на max или у функции нет шага); `−` — когда `prevStepPrice(current) === current`. Обе кнопки также disable'ятся, пока `placeBet.isPending`, чтобы предотвратить гонку значений во время запроса. Когда `step` в constraints отсутствует или нулевой — stepper вообще не рендерится, поле остаётся plain `Input` (контракт OpenAPI явно даёт `step: null` для части аукционов, и для них +/- кнопки бессмысленны).
- **SDD-027: `e2e/bet-form.spec.ts` — отдельный smoke для stepper-интеракции.** route-smoke проверяет только h1/section/alert (URL→content); stepper — это клиентская интеракция с RHF state, которая требует реального click + read input value. Добавлен 6-проверочный smoke: рендер +/- кнопок по aria-label, видимость подсказки "шаг N ₽", seed от available+step на первом клике `+`, корректность повторного шага, обратный шаг, submit-интерактивность. Живёт в `e2e/` рядом с route-smoke под `@playwright/test`.
- **SDD-030: chip = Badge + вложенная `<button>`, не кастомный Pill.** shadcn Badge уже даёт `h-5`/`rounded-full`/`variant=secondary`; добавляем внутрь `<button>` с `XIcon` (lucide) и `aria-label="Убрать фильтр: {label}"`. Кнопка `size-5` (совпадает с высотой Badge) — полный-height click target без визуальных артефактов. CSS-класс Badge `[&>svg]:size-2.5!` не применяется, потому что `XIcon` — не прямой child, а внутри button.
- **SDD-030: переиспользование `FIELD_KINDS` вместо нового descriptor-массива.** Чипам нужен тот же "что активно, что исключить" предикат, что и `countActiveFilters`. Вместо второго источника правды вынесены `FIELD_KINDS`/`ACTIVE_FIELDS`/`NON_FILTER_FIELDS`/`isActive` в Public API модуля `search-params.ts` (раньше были внутренними). Chip-builder и `removeFilterValue` читают ту же таблицу — добавление нового поля в форму автоматически расширяет и chip-логику.
- **SDD-030: один chip на значение массива, не один chip на поле.** GitHub/Linear-style: `auc_type=Down,Up` → два отдельных chip с собственными крестиками. Идентификаторы chip'ов стабильны (`${key}-${value}`), чтобы React-key не дёргался при частичном сбросе.
- **SDD-030: «Очистить всё» только в блоке chips, не в форме.** Форма уже имеет Reset (сбрасывает draft), а у chip-блока — своя кнопка (сбрасывает URL в defaults через `commitFilters`). Дублирование исключено: каждая кнопка живёт в своём контексте.
- **Пост-SDD рефакторинг: data-driven search-params через `FIELD_KINDS`.** Четыре функции (`serializeAuctionsListSearchParams`/`countActiveFilters`/`pickActiveFilters`/`buildAuctionListRequest`) итерировали одни и те же 16 полей с одинаковыми предикатами «не default». Введена `FIELD_KINDS`-таблица с kind-ами (`defaultNumber`/`defaultBoolean`/`string`/`optionalString`/`array`/`optionalNumber`/`optionalBoolean`) и один helper `isActive(key, value)` со switch по kind. Все 4 функции теперь итерируют `ACTIVE_FIELDS`. Добавление нового поля — однострочник в `FIELD_KINDS` + ключ в схеме, а не правка в 4 местах.
- **Пост-SDD рефакторинг: type guards вместо `as`-кастов.** `request-builder.ts` фильтровал `auc_type` через `(API_AUC_TYPES as readonly string[]).includes(value)` и затем кастовал результат `as AuctionListRequest['auc_type']`. Заменено на type guard `isApiAucType(value): value is ApiAucType` — фильтр сам сужает тип, каст не нужен. Для `status` каста вообще не осталось: URL-side enum — подмножество API-side enum'а, и TS пропускает assignment напрямую.
- **Пост-SDD рефакторинг: вынос `parseOptionalBoolean` в `@shared/lib/parse`.** Симметрично с существующим `parseOptionalNumber`. Локальный дубликат в `search-params.ts` удалён, модуль переиспользует общий helper через `@shared/lib`.
- **Пост-SDD рефакторинг: extraction через RHF context, не prop-drilling.** `PriceField` в bet-form и `ResetButton` в auction-filters достают `form.control`/`form.reset` через `useFormContext()`/`useController`, а не через пропсы. Это убирает пропс-др иллинг без введения новой абстракции — RHF-context уже существует, им просто пользуются.
- **Пост-SDD рефакторинг: drop premature `useMemo`/`useCallback`.** Промежуточная итерация обложила derivation-функции в `auctions-list.component.tsx` memo-хуками «на всякий случай». Удалены — они не уберегали от ре-рендера (внешнее состояние менялось каждый кадр) и добавляли шум. Правило: memo только там, где есть измеренный bottleneck.
- **Пост-SDD рефакторинг: сужение barrel `@features/auction-filters`.** Внутренние символы (`auctionsListFiltersSchema`, `DEFAULT_PAGE`, `DEFAULT_IS_OLDEST`, `parseAuctionsListSearchParams`, `serializeAuctionsListSearchParams`) убраны из публичного экспорта. Public API фичи теперь содержит только то, что реально потребляется внешними слоями — добавление новых internal-хелперов не раздувает публичный контракт.

## Какие AI-предложения были отклонены

- **Не приравнивать `auctionUuid` к `main.order_uid` в API-path'ах**: `order_uid` используется только как внешний `auctionRef` в UI/router, а преобразование в настоящий `auctionUuid` изолировано в adapter-layer resolver.
- Не генерировать React Query-хуки из OpenAPI.
- Не экспортировать сгенерированные артефакты напрямую в feature/entity-слои.
- Не использовать localStorage как источник истины для фильтров.
- Не прятать поток ставок вне иерархии маршрута аукциона.
- Не прыгать в реализацию фич до декомпозиции и архитектурных ограничений.
- Не использовать `z.coerce.number()` для цены в форме ставки — превращает `''` в `0` (false-positive «цена обязательна») и пропускает `NaN`. Заменено ручной coerc'ией в `superRefine`.
- Не цепочить `.refine()` для проверки цены — собрало бы все ошибки сразу; для UX формы нужно ровно одна ошибка на поле за раз.
- Не объединять `toPlainObject` и `normalizeRecordSearch` несмотря на одинаковую выходную форму `Record<string, string[]>` — у них разная входная семантика (URLSearchParams vs `Record<string, unknown>`), принудительное объединение сделает код хуже.
- Не вводить декларативные field-descriptor'ы преждевременно — waited, пока дублирование в 4 функциях не стало очевидным (post-SDD-028 рефакторинг), только тогда ввёл `FIELD_KINDS`.
- Не делать `ActiveFilterChips` настраиваемым через props — компонент самодостаточен, как `AuctionFilters`/`AuctionSearchInput`. Кастомизация через children/render-prop — premature.
- Не оборачивать derivation-функции в `useMemo`/`useCallback` без измеренного bottleneck'а — удалены как premature optimization.

## Что проверялось особенно внимательно

- OpenAPI-поля с `format: uuid` — Hey API эммитит их как `string`; `order_uid`, `auctionUuid`, UUID сид-аукционов используют каноническую форму.
- Контракто-чувствительные nullable-поля и различия enum'ов между list и detail.
- Валидация и обработка ошибок 422 (`ValidationProblem` с `errors[]`).
- DTO-driven UI-ограничения: скрытые контакты, скрытые цены, скрытая история ставок.
- URL-матчинг MSW: относительный путь сматчился в браузере, но не в Node — leading-wildcard решил обе среды.
- Пагинация за пределами диапазона: `page > last_page` исторически возвращала `meta.from > total`; фикс — `from=0, to=0` для пустой страницы, как Laravel-пагинатор.
- `await worker.start()` до `createRoot` — без race-condition между worker и первым fetch TanStack Query.
- Cross-endpoint консистентность после `writeBet`: smoke проверяет list/detail/bets согласованно.
- **MSW 2.x state lifecycle**: handlers исполняются в JS-контексте активной вкладки, не в Service Worker; полный `page.goto` переинициализирует bundle и сбрасывает module-level state в seed. E2e-флоу между экранами использует SPA-навигацию (click по `<a>`), чтобы state дожил до конца сценария — иначе mutation-flow-спека падала бы на третьем экране с "цена не обновилась".
- **NBSP в ru-RU `Intl.NumberFormat`**: `toLocaleString('ru-RU')` использует non-breaking space (U+00A0) как разделитель тысяч. Playwright `textContent` возвращает его как есть — regex-assertion в smoke построен как `digits.split('').join('[\\s\\u00A0]?')`, иначе точное сравнение `=== '44 000'` падало на невидимом символе.
- **camelCase ↔ snake_case граница**: OpenAPI-контракт отдаёт snake_case (`current_price_from`, `order_uid`); DTO типы и адаптеры держат snake_case до границы `entities/auction`, VM-mappers превращают в camelCase (`currentPrice`, `auctionRef`). UI никогда не видит snake_case. Это убирает случайные опечатки в JSX, но требует внимательности при добавлении новых полей — naming-convention переход явный, в mapper'е.
- **Type guards vs `as`-касты в request-builder**: post-SDD рефакторинг проверил, что TS действительно принимает assignment URL-статусов в API-статусы без cast'а (URL enum — подмножество API enum'а). Если будущая ревизия OpenAPI сузит API enum, это место.first упадёт в typecheck — preferable runtime failure.
- **URL contract edge cases**: round-trip parse ∘ serialize сохраняет falsy `is_available: false` (формально это фильтр); URL `?auc_type=Unknown` парсится, но request-builder отсекает `Unknown` через type guard перед отправкой в API.
- **Mock-only расширение `main.auction_uuid` (D-011)**: добавлено в mock-seed и в list-item тип mocks-side, но не протекает в production Public API `shared/api`. Проверяется grep'ом по `generated/` — должны отсутствовать.

## Какие риски остаются

- **Нет реального backend**. MSW — единственный источник ответов; адаптер `shared/api` структурирован так, чтобы реальный backend мог подключиться заменой mock-handler'ов, но интеграционного теста против не-mock сервиса нет. Любая расходимость между MSW-сидом и реальным контрактом (например, edge-case'ы nullable-полей, форматы дат, особенности пагинации) вылезет только на интеграции.
- **Продуктовые ожидания шире форм ответов OpenAPI** — некоторые UI-значения выводятся из доступных данных, а не приходят напрямую. Например, `step` торгов есть только в detail-DTO, в карточке списка не показывается; ограничение `noViewCargoPrice` физически не энфорсится в list-view, потому что list-item DTO не содержит этого флага (SDD-022).
- **Mock-only расширение `main.auction_uuid` (D-011)** bridging контрактный разрыв между paths и list-DTO. Не должно протекать в production-типы; гарантируется структурой `generated/` (read-only, isolated), но не тестом. При regen'ерации OpenAPI проверять, что поле не появилось в production-DTO.
- **`pnpm check` не включает browser smokes**. Logic-тесты (~314 в `pnpm test:run`) и typecheck/lint — fast loop на каждое сохранение; e2e Playwright smokes (21 в `pnpm test:e2e`) требуют запущенного vite dev-сервера и браузеров, запускаются отдельно. CI имеет смысл ставить в две параллельные джобы.
- **Visual regression и mobile-rendering не автоматизированы**. Дизайн адаптивный, но только `filters-ui.spec.ts` прогоняется на 375px viewport. Сломанная вёрстка на произвольном разрешении обнаружится только вручную.
- **shadcn dual-export pattern**: каждый `pnpm dlx shadcn@latest add ...` привозит компонент с двумя экспортами (component + cva/styles); oxlint-правило `react/only-export-components` требует ручного разделения на `*.component.tsx` + `*.styles.ts`. Если забыть разделить — fast-refresh сломается.
- **`react-hook-form` с input≠output типами** требует 3-generic signature (`useForm<TFieldValues, TContext, TTransformedValues>`) для Zod-схем с `.transform()`. На RHF < 7.83 это не работало бы; текущая версия зафиксирована в `package.json`, при bump'е нужно перепроверить.
- **Кросс-эндпоинт консистентность** проверена SDD-028 smoke как верифицированный инвариант; будущие UI-мутации не должны патчить кеш локально (`queryClient.setQueryData`) вместо инвалидации query-ключей через `betMutationInvalidationTargets`. Инвалидация держит три экрана согласованными без ручных правок.
- **Chip `is_available: false`-ветка** теоретически достижима через URL (парсер принимает), но форма её не порождает. Chip показывает `"Только доступные: нет"` — если бэкенд когда-нибудь добавит семантику inverse-mode, текст надо будет пересмотреть.

## Что улучшилось бы при наличии ещё одного дня

- **Tooltips для truncated values** в карточке и detail (длинные названия городов, грузы, организации). SDD-019 явно отложил это; сейчас truncate обрезает молча, на мобильных это особенно заметно. shadcn Tooltip + detect-overflow-хук — стандартная работа на полдня.
- **Visual regression / snapshot tests** через Playwright screenshots или Percy/Chromatic. Сейчас верстка проверяется только глазами и одним 375px smoke'ом; сломанный layout на любом другом разрешении обнаружится только пользователем.
- **Расширение mock edge-cases**: больше комбинаций restriction-флагов, экзотические даты (високосные года, конец квартала), отрицательные цены в истории ставок (если бизнес-логика когда-нибудь допустит), длинные списки ставок (50+) для проверки virtualization-ready render'а.
- **Toast infrastructure** для success/error feedback. Сейчас success ставки подтверждается навигацией на `/bets` (хитро, но не universal pattern), error — inline Alert. shadcn Sonner дал бы унифицированный канал для всех мутаций.
- **Accessibility audit**: keyboard navigation по всем интерактивным элементам, focus-trap в filter sheet (сейчас закрывается по Esc и backdrop, но tab-порядок не формализован), ARIA-атрибуты для dynamic regio ns (live regions для ошибки ставки).
- **Component-level тесты для форм** (React Testing Library) — сейчас bet-form покрывается e2e, что медленно. Component-тест на Zod-error rendering, ApiValidationError mapping и stepper edge-cases ускорил бы red-green цикл.
- **Real backend integration test** — хотя бы один тест, который ходит против бойлерплейт-API (не MSW), чтобы validate adapter и SDK на реальном HTTP, а не только против mock-handler'ов.
- **perf budget и Lighthouse baseline** в CI — карточки сейчас отображаются через VM-mapper в `select`, но large lists (1000+) не тестировались; заложить metric threshold'ы до того, как начнётся optimization-by-guess.
- **CI matrix** на Linux/macOS/Windows — сейчас все скрипты выполняются локально на macOS, нативные зависимости (`@playwright/test`, `oxfmt`, `msw`) могут удивить на других платформах.
